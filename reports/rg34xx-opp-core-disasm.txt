反汇编语义（伪代码）：
    opp_table = [x29,#0x88];
    M   = opp_table->supported_hw;        // 0x160
    cnt = opp_table->supported_hw_count;  // 0x168
    if (M == NULL) {
        if (of_find_property(opp_np, "opp-supported-hw", NULL))
            -> SKIP this OPP;             // 0x84bdaf8 cbnz -> 0x84bdb6c
        else
            -> ACCEPT;                    // 0x84bdafc b    -> 0x84bdb74
    } else {
        for (i = cnt-1; ; i--) {
            if (i < 0) -> ACCEPT;                              // 0x84bdb18 cmn w5,#1; b.eq accept
            if (of_property_read_u32_index(np,"opp-supported-hw",i,&val)) {
                dev_warn(...); -> SKIP;                        // 0x84bdb50
            }
            if ((M[i] & val) == 0) -> SKIP;                    // 0x84bdb10 tst; b.eq skip
        }
    }

关键结论：
  · 匹配条件是 **(M[i] & node_bitmap[i]) != 0**，即“至少一位重叠”即可，不是全位包含。
  · 当 mask 未注册时，**凡是带 opp-supported-hw 的节点一律被剔除**，只留下不带该属性的节点。
  · 带 mask 注册时，**没有 opp-supported-hw 的节点仍然被接受**（不会因缺属性被过滤）。
  · 缺 opp-supported-hw 的节点在“注册了 mask”时**不会**被过滤——过滤只发生在“未注册 mask
    且节点带属性”这一种组合。

七、五情形模拟（基于上面的实际反汇编谓词）
--------------------------------------------------------------------------------
设：节点 N 的 opp-supported-hw 位图为 B（u32 数组），注册掩码为 M。
    接受谓词 =   (M==NULL 且 N 无 opp-supported-hw)
             或 (M!=NULL 且 (N 无 opp-supported-hw 或 存在 i: (M[i]&B[i])!=0))
    电压来源 =   prop_name ? "opp-microvolt-<prop_name>"(缺则回退 base) : base

先声明：本探针**不可能**同时设置 mask 与 name——mask 组（0x2400/0x5000/0x5400/0x7400→1，
0x2c00→2，默认→8）name 恒为空；a/b/c 组 mask 恒为 0。故“mask=1/2/8 + b1”只是假设情形，
不是本探针可达状态。

| 情形 | mask | prop_name | 接受集合（相对 38 节点）                               | 电压 |
|------|------|-----------|--------------------------------------------------------|------|
| ①    | 无(0)| b1        | 仅“无 opp-supported-hw”的节点                          | b1(回退 base) |
| ②    | 1    | b1(假设)  | 无属性节点 ∪ B&1!=0 节点                              | b1(回退) |
| ③    | 2    | b1(假设)  | 无属性节点 ∪ B&2!=0 节点                              | b1(回退) |
| ④    | 8    | b1(假设)  | 无属性节点 ∪ B&8!=0 节点                              | b1(回退) |
| ⑤    | 探针实得 | 探针实得 | 若走 a/b/c：(=①，mask=0，电压用该前缀名)；若走 mask 组：(=②/③/④ 但只回退 base) | 见左 |

对九档频率集合 {480,720,936,1008,1104,1200,1320,1416,1512} MHz 的判定：
  · 这 9 个值是“某一硬件 bin 的完整单调集合”（无 1608/1800 等更高档，说明不是全表）。
  · **若**这 9 个目标节点是 DTB 中“不带 opp-supported-hw”的那一组（最自然的供应商写法：
    每个 bin 用命名电压区分、用 supported-hw 区分不同硬件版本），
    则**只有 mask 未注册的①（等价于 ⑤ 的 a/b/c 分支）恰好得到 9 个**；
    任何 mask=1/2/8 分支都会把带对应位的节点也纳入，得到 >9 个（除非 DTB 人为把其余节点
    标成别的位——但那样就应直接走①）。
  · 若这 9 个节点恰好是“带 B&1”的节点，则也只有②能得 9 —— 但这与 probe 的 b1 命名机制
    重叠冗余，且②在探针里不可达（mask 组 name 为空）。
  · 因此最可能复现九档的是 **情形①（mask=0 + prop_name=b1）**，即 0x6c00/0x7c00 在
    soc_ver&7!=0 时生成的 “b1”；电压取 opp-microvolt-b1，缺失则回退基础 opp-microvolt。
    置信度：中（依赖“9 个目标节点不带 opp-supported-hw”这一 DTB 前提）。
  · 由于 ELF 内无 DTB，“38 个节点”的各 B 值无法离线获取，故无法把①②③④从**频率个数**
    上绝对证伪；上面给的是基于代码结构的最优推断。**要给出唯一结论必须有目标 DTB。**
