# armgba_libretro.so — 运行时映射（/proc/PID/maps）

只读采集，仅 ADB。未读取 `/proc/PID/mem`，未创建 trace 标记，未设置 `SLOT_TRACE_LATENCY`，
未重启/停止 Slot，未改任何配置，未写任何寄存器。

采集时间：2026-11-26 00:13 UTC（设备 `uptime` 约 3699 s，即开机约 1 小时后）

## 1. 按 cmdline 找 Slot PID（不沿用旧 PID）

不写死 PID，改为遍历 `/proc/*/cmdline`，按二进制路径匹配：

```sh
for d in /proc/[0-9]*; do
  p=${d#/proc/}
  c=$(tr "\0" " " < $d/cmdline 2>/dev/null)
  case "$c" in *"/System/slot"*) echo "$p|$c";; esac
done
```

设备实际输出（第二条是执行该命令的 shell 自身，需排除）：

```
2301|/lib/ld-linux-aarch64.so.1 /mnt/sdcard/System/slot
8399|/bin/sh -c for d in /proc/[0-9]*; do ... done
```

结论：本次 Slot PID = **2301**，`argv[0]` 是动态链接器，`argv[1]` 才是 `/mnt/sdcard/System/slot`。
PID 数值与上一轮相同属于巧合（设备已重启，旧进程早已退出），判定依据是 cmdline 而不是数值。

## 2. `/proc/2301/exe`

```
lrwxrwxrwx 1 root root 0 Nov 25 23:13 /proc/2301/exe -> /usr/lib/aarch64-linux-gnu/ld-linux-aarch64.so.1
readlink -f: /usr/lib/aarch64-linux-gnu/ld-linux-aarch64.so.1
```

`exe` 指向动态链接器而非 `slot` 本体 —— 这与 cmdline 一致：Slot 以 `ld-linux-aarch64.so.1 /mnt/sdcard/System/slot`
的方式启动（显式指定解释器），所以 `/proc/PID/exe` 记录的是解释器。**不能用 `/proc/PID/exe` 判断核心是谁**，
判定主程序要看 `maps` 里 `slot` 的那几行（`r-xp 00000000` 起、`b3:07` 设备号、路径 `/mnt/sdcard/SYSTEM/slot`）。

## 3. 本次采集结果：核心未加载

```
grep -c armgba /proc/2301/maps   →  0
```

`maps` 共 414 行，其中带路径的共享库只有 12 个：

```

/usr/lib/libEGL.so.1
/usr/lib/libGLESv2.so.2

```

`armgba_libretro.so` 不在其中，说明**当前 Slot 处于前端 UI 状态，尚未 `dlopen` 任何 libretro 核心**。
这与上一轮“进游戏只 `dlopen` 不重启进程”的结论吻合：核心映射只在游戏运行期间存在，
一退出游戏就会被 `dlclose` 掉，`maps` 里随即消失。

因此本轮**没有**得到 `armgba_libretro.so` 的运行时映射行，`load-bias.json` 的 `captured` 字段保持 `null`。
这不是采集失败，而是状态不满足：需要在游戏运行中点采集。判定条件写在下一节。

## 4. 游戏运行时应采集的命令（原样，只读）

```sh
# 1) 重新按 cmdline 定位（不要复用 2301）
for d in /proc/[0-9]*; do p=${d#/proc/}; c=$(tr "\0" " " < $d/cmdline 2>/dev/null); \
  case "$c" in *"/System/slot"*) echo "$p|$c";; esac; done

# 2) 确认核心已加载（应 >= 1）
grep -c armgba /proc/PID/maps

# 3) 取该库的全部映射行（可能有 3~5 行）
grep armgba /proc/PID/maps

# 4) 取进程 exe（同 §2，仅作记录）
readlink -f /proc/PID/exe
```

## 5. 预期映射形状（由 PT_LOAD 推算，待实测替换）

`armgba-pt-load.txt` 给出两个 PT_LOAD；按 4 KiB 页对齐展开，预期出现下面这类行
（`bias` 为未知量，三行必须解出同一个 `bias`）：

| 预期行 | 权限 | offset 字段 | 起始地址 | 长度（页对齐） | 来源 |
| --- | --- | --- | --- | --- | --- |
| #1 | `r-xp` | `00000000` | `bias + 0x000000` | `0x176000` | PT_LOAD #0（RX，`p_vaddr=0`） |
| #2 | `r--p` | `00175000` | `bias + 0x185000` | `0x4000`（RELRO 边界决定） | PT_LOAD #1 头部（`.data.rel.ro`/`.got`） |
| #3 | `rw-p` | `00189000` | `bias + 0x189000` | 至 `bias + 0x65e000` | PT_LOAD #1 尾段 + `.bss` 零页 |

说明：`#2`/`#3` 的切分点取决于链接器 RELRO 结尾，实际可能是 2 行也可能是 3 行；`#1` 一定存在且一定从
`offset 00000000` 开始，所以 `bias` 的主解算用 `#1`，`#2`/`#3` 只作交叉验证。
