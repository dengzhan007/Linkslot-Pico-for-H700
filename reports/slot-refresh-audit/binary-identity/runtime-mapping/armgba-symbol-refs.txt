# armgba_libretro.so — retro_* 反汇编与两个 `gba` 同名 LOCAL OBJECT 的引用溯源

离线只读分析。二进制为设备 `SYSTEM/armgba_libretro.so` 的逐字节副本（SHA-256 见上级目录 `REPORT.md`，此处不再重复）。
反汇编引擎：capstone 5（`CS_ARCH_ARM64`）；符号：`.symtab`（未 strip）；GOT：`.rela.dyn` 的 `R_AARCH64_RELATIVE`。

## 1. 目标符号

| 符号 | 地址 | 大小 | 类型/绑定 | 所属段 |
| --- | --- | --- | --- | --- |
| `retro_run` | `0x1f560` | 10264 | FUNC / GLOBAL | `.text` |
| `retro_load_game` | `0x1cf60` | 512 | FUNC / GLOBAL | `.text` |
| `retro_unload_game` | `0x1d470` | 1224 | FUNC / GLOBAL | `.text` |
| `gba` | `0x4c16a8` | 8 | OBJECT / **LOCAL** | `.bss` |
| `gba` | `0x4259b8` | 8 | OBJECT / **LOCAL** | `.bss` |

两个同名符号都是 `STB_LOCAL`（文件内静态），大小均为 8 字节 —— **是指针变量，不是 `struct GBASystem` 本体**。
符号名相同意味着它们来自两个不同的编译单元，不能靠名字区分，只能靠引用关系。

## 2. 主指针 `0x4259b8` 是通过 GOT 访问的

`.rela.dyn` 里恰有一条 `R_AARCH64_RELATIVE`（type 1027）的重定位，addend 指向该对象：

```
r_offset = 0x00187d58   r_info_type = 1027 (R_AARCH64_RELATIVE)   r_addend = 0x004259b8
```

`0x187d58` 位于 `.got`（`0x187a60`–`0x187fe8`）。因此代码里的访问序列是两跳：

```
adrp x21, 0x187000
ldr  x0,  [x21, #0xd58]     ; x0 = &gba        （GOT 槽装的是对象地址 0x4259b8）
ldr  x0,  [x0]              ; x0 = gba         （取出指针本身）
```

另一侧的 `0x4c16a8` **没有** GOT 槽，全部是 `adrp`+`ldr/str` 直连（基址多为该编译单元自己的 `$d` 锚点 `0x4c1638`，偏移 `+0x70`）。

## 4. 写入点：谁给这两个指针赋值

对 `0x4259b8`，全 `.text` 里只有两处写：

| 位置 | 指令 | 所在函数 | 含义 |
| --- | --- | --- | --- |
| `0x1a9ac` | `str x2, [x22]`（x22 = GOT[&gba]） | `loadAdvance.part.0` | 装入新核心：`gba = 新建的 GBASystem*` |
| `0x1d6f0` | `str xzr, [x1]`（x1 = GOT[&gba]） | `retro_unload_game` | 卸载：`gba = NULL` |

`loadAdvance.part.0` 的赋值上下文（`0x1a978`–`0x1a9b8`）：

要点：`bl 0x19be0`（`startAdvance`）返回 x0 = 新建核心；随后同一个值 x2 被同时写进
`gbas`（`GOT[0x187d68]`，`struct GBASystem *gbas[4]`，32 字节）与 `gba`（`GOT[0x187d58]`）。
`gba` 是 `gbas[0]` 的**当前活动别名**，先建后发，`retro_run` 每帧从它取核心。

对 `0x4c16a8`，唯一写者是联动模块自己的 setter：

| 位置 | 指令 | 所在函数 | 含义 |
| --- | --- | --- | --- |
| `0x3318c` | `str x19, [x1, #0x70]`（x1 = 0x4c1638） | `linkSetGba` | 联动模块缓存一份核心指针 |
| `0x33228` | `str xzr, [x1, #0x70]` | `linkSetGameBoy` | 切到 GB 模式时清空 |

`linkSetGba` 的调用者（谁把指针交给联动模块）：

```
  0x0001a39c  bl     in startOthers
  0x0001a4b4  bl     in startOthers
  0x0001ab08  bl     in loadAdvance.part.0
  0x0001ac74  bl     in loadAdvance.part.0
  0x0001acc0  bl     in loadAdvance.part.0
  0x0001d698  bl     in retro_unload_game
  0x0001dd40  bl     in retro_reset
```

全部出现在“核心刚建立/刚销毁”的路径上（`startOthers`、`loadAdvance.part.0`、`retro_unload_game`、`retro_reset`），
说明 `0x4c16a8` 只是**下游缓存**，随主指针被动更新，从不反向决定 `gba`。

## 5. 结论：`0x4259b8` 是主 GBA 指针

三条互相独立的证据：

1. **赋值源**：唯一直写者 `loadAdvance.part.0` 把 `startAdvance()` 的返回值写进去，且与 `gbas[0]` 同源同值；`0x4c16a8` 的写入者是 setter，输入参数就是主指针。
2. **访问面**：`0x4259b8` 被 19 个函数引用（含 `retro_run` 21 处、`retro_unload_game`、`retro_reset`、`retro_serialize/unserialize`），是整帧执行路径上取核心的入口；`0x4c16a8` 只被 12 个联动函数引用。
3. **生命周期**：`retro_unload_game` 先 `linkSetGba(NULL)` 再 `gba = NULL`（先断下游、再断源头），顺序本身表明谁是源。

因此：**`gba @ 0x4259b8` 是主 GBASystem 指针（libretro 前端编译单元持有）；`gba @ 0x4c16a8` 是联动（link cable）编译单元持有的同值缓存副本。**
两者在游戏运行期间相等，但只有前者是“源”。
