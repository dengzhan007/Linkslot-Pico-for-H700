# H700 no_std Linkslot frontend business crates

This directory is the first persistent device-side Rust business slice. It is derived from the immutable user-provided Linkslot 1.0.36 source snapshot on `upstream/linkslot` (snapshot commit `8590d6ff1b2caa26118051069c975106fbb14bd3`; this is an archive identity, not an upstream Git commit).

## Crate contents

- `slot-input`: Linkslot raw button events, button enum, gesture state machine and action vocabulary. The only runtime substitutions are `std::mem::take` → `core::mem::take` and explicit `alloc` imports.
- `slot-model`: Linkslot static machine/core tables, platform metadata, battery/charge types and card directory constants. Filesystem-specific `resolve_root(PathBuf)` and `Platform::accepts(&Path)` helpers are intentionally excluded; device path access belongs to the H700 VFS/runtime service, not the pure business model.
- `slot-frontend-state`: the pure `FacesLang` build coordinator extracted from Linkslot `Frontend`; it is generic over the language ID and owns only baked/building/generation state. Worker threads, texture construction, and result delivery remain the caller's responsibility.
- `slot-core-picker`: the generic `CorePicker<C>` extracted from Linkslot `App`; it retains option navigation, single-core information-only behavior, hop reversal, open/close easing, edge refusal feedback and the selected-core write result. It does not depend on `slot-store`, `slot-ui` or the GL renderer.
- `slot-link-state`: Linkslot's paired-GBA save-state codec (`SLK1`) and BIOS identity comparison. The parser validates both length-prefixed states and rejects truncation, trailing bytes and invalid player indices; the hot BIOS inspection path borrows the source slice rather than cloning the full save state.
- `slot-link-kind`: the pure game-code/title classifier for cable versus wireless GBA link, including the verified retail Pokémon exception table and Libretro serial-option mapping. It has no platform, networking, file or simulator dependency.
- `slot-video-mode`: the `VideoMode` value and normalized source-rectangle crop policy. Parsing is allocation-free and source crop computation receives frame/picture dimensions; INI read/write remains in the host-only `slot::video_mode` wrapper.
- `slot-video-mode`: the `VideoMode` value and normalized source-rectangle crop policy. Parsing is allocation-free and source crop computation receives frame/picture dimensions; INI file access remains in the host-only `slot::video_mode` wrapper.

The packages have no third-party crate dependencies and compile as `no_std`; allocation-bearing APIs use `alloc`. `slot-model` enables its `host-compat` default feature for the original Linux path helper API. Freestanding checks and the LK candidate must use `--no-default-features`, which removes those `std::path` helpers while preserving the domain data API. `slot-input` contains the versioned H700 C Input Service v1 adapter: C supplies ordered logical button edges, Rust `H700InputSource::drain_into()` maps them to the upstream `RawEvent` type without allocating a per-poll vector, and `H700GestureInput` forwards them into the original Linkslot gesture state machine. The 64-event C queue is a single-context primitive; board GPIO/ADC scanning is not yet implemented. The caller retains ownership of the C service table and queue.

## Target boundary

These crates do not read GPIO, MMIO, clocks, files, or framebuffer memory. The H700 C layer must provide the allocator and input/time services before device runtime code calls allocation-bearing APIs. Do not enable the allocator or call these crates from a booting target until the LK heap, memory ownership, and single-active-CPU gate are approved.

They are a selected business-logic slice, not a complete Linkslot frontend. The Linux `device_app`, `slot::App`, filesystem workers, network/WebDAV, SQLite, dynamic loading, full artwork/font stack and UI event loop have not been made bare-metal.

The generic `FacesLang` state machine has six host tests for first build, matching language, rapid-change coalescing, stale-generation rejection, abandoned worker retry and synchronous completion. It is compiled as `no_std` for AArch32/AArch64 and is injected back into the real Frontend by the temporary source overlay.
The generic `CorePicker<C>` carries six host tests for startup/open timing, direction and edge refusal, mid-hop reversal continuity, single-core non-write behavior, commit-and-close, and hop completion. It is also compiled as `no_std` for AArch32/AArch64 and replaces the original `App` picker type through the temporary overlay.
The paired link-state codec has seven host tests for round-trip and per-player extraction, malformed length/trailing data, player bounds, BIOS matching/mismatch and conservative handling of short/unknown states. It is `no_std + alloc` and retains the original `slot::link_state` public functions through a re-export.
The link-kind policy has eight tests covering known wireless codes, verified clean retail Pokémon behaviour, hack/unknown title fallbacks, link-capability flags and cable/wireless serial protocol strings. It compiles as `no_std` for AArch32 and AArch64.
