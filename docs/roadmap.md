# 开发路线与阶段验收

本项目采用可验证的垂直切片推进。每一阶段都必须产出可重复构建的测试对象和明确的验收记录；不以“编译通过”代替设备验证。

## M0：项目基线（当前）

- [x] 建立独立仓库。
- [x] 确认产品方向：GammaOS Pico 裸机架构参考 + Linkslot 唯一前端。
- [x] 确认首期只做 GB/GBC/GBA。
- [x] 固化关机、手动电池存档、手动云同步、家庭 LAN Web 和调试规则。
- [x] 确认目标设备无 eMMC，只设计 SD 卡启动，不做旧系统自动回退。
- [x] 确认 Linkslot 上游 subtree 同步和 H700 适配隔离策略。
- [ ] 完成目标设备清单，锁定第一台 H700 实机及其屏幕/音频/Wi-Fi/USB 型号。
- [ ] 完成 Linkslot 逐 crate 依赖审计，确定可原样复用、需要适配和必须替换的模块。
- [ ] 验证 H700/LK 工具链中的 Rust 运行时方案；确认需要的最小任务、文件、网络与时间服务。

## M1：H700 SD 启动原型

交付：从 SD 卡启动的最小 AArch64 裸机 payload，只显示串口日志和色块，不依赖 Linux。

验收：

- 能从目标 U-Boot 稳定加载 payload；
- 读取板型/内存信息并建立正确的内存图；
- 通过 GPIO 读取确认过的按键；
- 不写入 eMMC，不要求存在 eMMC；
- 至少 100 次冷启动均能进入 payload；
- 记录从电源键到第一帧的分段耗时；
- 启动失败的恢复方式有明确的 SD 卡重写/设备烧录说明，不把自动回退到原 Linux/BaseOS 作为条件。

## M2：运行时基础 HAL

交付：定时器、内存/cache、调度、SD 块设备与文件系统、日志、GPIO 输入、显示输出、PCM 音频。

验收：

- FAT32/exFAT 读写和异常断电恢复测试；
- 显示刷新无撕裂，目标面板按正确方向/分辨率工作；
- 输入无丢键、无重复长按；
- 长时间 PCM 连续播放无爆音/欠载；
- 不启动 Linux，不进入 suspend；
- H700 adapter 不依赖 Linkslot UI crate，Linkslot 只能通过已定义的服务接口使用硬件能力。

## M3：单核心垂直切片

交付：先选一个最简单的 GB ROM，打通 ROM 读取、Core ABI、视频、音频、输入、即时状态、电池存档。

验收：

- 可连续运行 30 分钟；
- 帧率与声音稳定；
- 即时存档保存/载入可重现；
- 电池存档只有用户显式保存时才落盘；
- 不调用 Linux API，不依赖系统进程。

## M4：GB/GBC/GBA 与 Linkslot 唯一前端

交付：GB/GBC/GBA 三个平台；Linkslot 卡带库、封面、最近游玩、收藏、核心选择、游戏内菜单。

验收：

- 三平台至少各 20 个代表性游戏完成兼容性抽测；
- 核心崩溃不会破坏游戏库和已有存档；
- 游戏核心切换后即时存档目录隔离；
- GB/GBC 调色板和色彩校正可独立设置；
- 核心菜单、热键和控制映射可配置；
- 同步一版 Linkslot 上游时，能够通过 subtree 更新、适配检查和回归流程完成构建，不需要重新移植 H700 HAL。

## M5：显示效果与金手指

交付：统一 compositor、校色、LCD 滤镜、Overlay/Bezel/遮罩、Cheats。

验收：

- 滤镜可逐项关闭，默认设置不导致明显帧率下降；
- Overlay PNG alpha 合成正确，可按平台/游戏选择；
- 金手指可以启用/停用/组合，重启游戏后配置持久化；
- 对 GBA、GBC 各至少验证一组真实金手指。

## M6：家庭 LAN Web 管理

交付：H700 Wi-Fi 驱动、DHCP/DNS、TCP Server、HTTP API 和 Linkslot Web 静态页面。

验收：

- 服务只在家庭 LAN 私网接口可见；
- 默认无密码；可选密码/配对令牌可以在页面上启用、修改和重置；
- 无公网监听；Wi-Fi 断开后服务不可达；
- 可浏览游戏库、管理资料、上传/下载电池存档和查看 MOD；
- 游戏运行期间 Web 写操作按一致性规则禁用或排队。

## M7：WebDAV 云同步

交付：保留 Linkslot 的云端布局、SHA-256、版本仲裁、冲突提示、备份和安全替换语义。

验收：

- 支持用户配置的 WebDAV 地址、TLS、用户名/密码和远程目录；
- 冲突不自动覆盖；用户选上传/下载后先备份再提交；
- 网络断开、超时或断电不会破坏本地存档；
- 只有显式点击同步才发起网络同步；
- 长按关机绝不调用同步代码。

## M8：MOD 与开发调试

交付：Lua 运行时、Linkslot MOD 目录/API、USB ADB（首选）或可用 SSH 通道。

验收：

- 原有 MOD 至少有示例集通过 API 兼容测试；
- Lua 有内存/执行时间/请求数量上限；
- 调试构建可通过 USB 连接读取日志、执行命令和传输文件；
- 生产构建默认关闭远程调试，用户可在设备端主动开启；
- 调试服务不依赖待机，不因调试开启阻止完全关机。

## M9：完全关机与正式验收

交付：PMIC 断电、关机事务、开机恢复和完整 SD 卡发行包。

验收：

- 长按电源键只写即时恢复状态；电池存档和云同步均不自动触发；
- 文件 flush 与断电顺序可审计；
- 正常关机后不进入 suspend/s2idle；
- 下一次开机可恢复上次游戏状态；
- 网络断开、云端冲突、MOD 故障不会阻止关机；
- 冷启动到可操作游戏库的时间有实测数据并纳入发布说明。

## 开发原则

1. 不跨阶段同时引入多个新硬件风险。
2. 每个驱动必须有独立探测/诊断页或可读日志。
3. 功能实现与验收测试同一个 PR 提交。
4. 任何跨核心存档兼容结论必须附真实文件、SHA-256、长度和复现步骤。
5. 先支持一台明确型号，再扩展其他 H700 设备 profile。
6. 跟进 Linkslot 上游时优先同步原始代码，避免将 H700 特定逻辑写入上游业务模块。
