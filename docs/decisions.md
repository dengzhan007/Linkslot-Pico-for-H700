# 已确认的设计决策

本文记录产品与架构的强约束。实现可以改变内部技术方案，但不得悄悄改变用户可见行为；需要改变时先更新本文件。

## ADR-001：产品范围

**决定：** 不完整移植 GammaOS Pico 前端。使用 GammaOS Pico 的裸机运行理念和可复用底层设计；UI 与用户功能以 Linkslot 为准。

首期仅开放 GB、GBC、GBA。不得将 FC/SFC/MD 等平台带入首期启动路径。

## ADR-002：家庭 LAN Web 管理

**决定：** Web 管理按家庭 LAN 工具设计，默认不强制密码。

- 服务只绑定设备 Wi-Fi 的私网 IPv4 地址；不监听公网/WAN，不实现端口映射或云端反向隧道。
- Web 页面显著显示设备 IP 与访问地址；离开 Wi-Fi 或网络断开时服务停止或不可达。
- 设置中预留“启用访问密码/配对令牌”开关。默认关闭；启用后可在设备菜单或 Web 设置页简单修改/重置。不能要求用户编辑配置文件。
- 上传、删除、存档读写和 MOD 管理均属于写操作；认证启用时所有写 API 必须受保护。
- Web 页面不显示 WebDAV 密码；MOD 的远程凭据仍由受控 Host API 管理。

## ADR-003：电源键与存档语义

**决定：** 长按电源键只保存即时恢复状态，然后完全关机。不触发电池存档写入、不触发云同步、不运行关机 MOD。

关机事务顺序：

1. 在帧边界暂停模拟器，拒绝新的游戏输入。
2. 序列化当前游戏即时恢复状态（包含恢复所需的模拟器机器状态），写入临时文件。
3. 校验长度/格式并原子替换正式 resume/state 文件，执行文件系统 flush/barrier。
4. 关闭音频 DMA/功放、背光、Wi-Fi 和非必要外设，执行 H700 专属完全断电。

**电池存档由用户显式保存。** 运行中的核心可以在内存中更新 SRAM/Flash/EEPROM，但关机路径不得把该缓冲区写入 `Saves/`。游戏内菜单、游戏库或 Web 管理提供明确的“保存电池存档”操作。

**云同步由用户显式触发。** 仅用户从设备菜单或家庭 LAN Web 页面选择“同步云存档”后运行。关机、启动、退出游戏、自动保存即时状态均不得触发同步。

结果提示必须区分“即时状态已保存”“电池存档已写入”“云端同步完成”，不得把三者合并成一个“已保存”。

## ADR-004：模拟器首选

| 平台 | 默认核心 | 备选/候选 | 决定依据 |
|---|---|---|---|
| GB | Gambatte | mGBA | Gambatte 为 GB/GBC 专用、准确性导向；mGBA 作为可选项 |
| GBC | Gambatte | mGBA | 优先准确性、调色板和 GBC 色彩校正；保留 mGBA 作为可选项 |
| GBA | mGBA | gpSP | 以 Linkslot 已有核心和存档路径为基线；gpSP 为兼容性/性能备选 |

armGBA-pico 暂列实验候选，而非正式默认核心。它在 GammaOS Pico 参考树中已完成 A32 recompiler、LCD 模型、核心选项与金手指集成，且声明与 gpSP 共用电池存档布局；但该声明没有证明其保存文件与 Linkslot mGBA 的文件字节兼容。完成 mGBA ↔ armGBA 的 SRAM/Flash/EEPROM 实机验证前，不切换默认核心，不混用即时存档。

## ADR-005：显示效果与游戏工具

**决定：** 保留并继续提供用户态显示和游戏工具，不因去掉 Linux 而删减。

首期要求：

- LCD 校色、色彩校正与 GB/GBC 专用调色板；
- LCD 滤镜（例如像素网格/扫描线/ghosting 等，以实际核心和渲染性能为准）；
- 可选 Overlay/Bezel/遮罩，采用独立透明图层并可按平台/游戏覆盖；
- 金手指：至少支持 Linkslot 现有 `.cht` 数据和常见 GameShark/Action Replay 格式；
- 快进、倒带、即时存档/读档、按键映射和每核心选项。

滤镜与遮罩必须有性能档位；默认效果不得让 GBA 无法稳定达到目标帧率。显示效果应尽量放在统一 compositor 中，核心本身的专属 LCD 模型作为单独选项。

## ADR-006：开发调试入口

**决定：** 调试访问是开发阶段的必需能力，正式版默认关闭网络调试服务。

- 优先实现 USB ADB gadget（开发构建或用户主动打开调试模式）；至少提供日志读取、shell/命令执行和文件推送/拉取。
- Wi-Fi SSH 作为后续可选调试通道，依赖 H700 Wi-Fi 与 TCP Server 完成；默认关闭，用户在设备端主动开启。
- 串口/早期启动日志、崩溃记录、启动阶段计时必须保留，作为 ADB/SSH 不可用时的调试入口。
- 不为 ADB/SSH 保持设备待机；只在设备正常运行时接受连接。

当前上游 LK 中的 USB/Fastboot 代码不等于已经具备 ADB。标准 ADB 需要单独实现 USB gadget transport 和 ADB protocol；SSH 也需要 TCP Server、加密和认证，不能把 Pico 的 TCP/TLS 客户端直接称为 SSH 服务。

## ADR-007：功能触发规则

- 云同步：手动触发；成功/冲突/失败都在 UI 中明确显示。
- 电池存档写入：手动触发；可提供单游戏和全库操作。
- 即时恢复状态：按用户设置自动写入；长按电源键必须写入一次。
- MOD：保留 Linkslot 执行时机及显式手动动作；关机路径不运行 MOD。
- Web：家庭 LAN 内访问；不因 Web 功能常驻设备或阻止完全关机。

## ADR-008：数据可移植性

尽量沿用 Linkslot 的 `Games/`、`Saves/`、`States/`、`Cheats/`、`linkSlot/Config/`、`linkSlot/Metadata/` 和 `linkSlot/mods/`。无法兼容的核心即时存档必须以核心 ID/版本隔离；不得将不兼容状态文件覆盖到另一个核心目录。

## ADR-009：单一前端

**决定：** 本项目只有 Linkslot 一个前端，不建设多前端管理、动态前端加载、前端插件接口或通用 Frontend ABI。

架构抽象优先服务于 H700 硬件隔离和 Linkslot 上游同步，不为了未来尚未提出的多前端需求增加运行时、存储布局或 UI 复杂度。将来真的更换前端时，再针对新前端做一次性适配；不要求现在为任意前端预留插件兼容。

## ADR-010：Linkslot 上游同步策略

**决定：** 优先降低跟进 Linkslot 上游版本时的代码改动量和冲突面，不要求直接安装原版 Linkslot 发布包，也不要求 H700 端能原样运行上游二进制。

- Linkslot 上游源码通过 Git subtree 固定放在 `third_party/linkslot`，以具体 commit SHA 为版本基线。
- H700/LK 代码放在 subtree 之外；Linkslot 的平台相关调用通过窄适配层提供。
- 优先复用上游用户逻辑、数据格式、UI 资源、Web 页面、同步协议和 MOD 规范。
- 只有确实需要时才修改 subtree 内源码；每个本地补丁必须有记录和回归测试。
- 每次同步上游后先生成差异报告、编译复用部分并运行兼容测试，再更新正式基线。
- 不建设完整 POSIX/Linux 兼容层。若某个上游模块的系统依赖太深，允许只复用其协议、数据模型和可独立测试逻辑，并在 H700 侧替换该模块。

## ADR-011：SD 启动，无 eMMC 回退

**决定：** 目标设备无 eMMC，本项目只考虑 SD 卡启动，不设计 eMMC 写入、双系统启动选择或自动回到原 Linux/BaseOS 的回退机制。

启动链原型只需验证 SD 加载、内存交接、裸机入口和正常冷启动。设备无法启动时，恢复路径是通过电脑修复/重写 SD 卡或使用设备真实存在的 Boot ROM/USB 烧录入口；不把运行时回退作为验收条件。
